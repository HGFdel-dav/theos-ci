## 定因（机器码证据）
坏包 `ParallelXClone.dylib` 的 `PXCloneClassResponds` 函数 (0xc228) 在同一个 LR/SP 状态下连续执行两次 `pacibsp` (0xc238, 0xc23c)，return 路径连续执行两次 `autibsp` (0xc254, 0xc258)，然后 `ret`。第一次签名的 LR 被第二次再次签名；一次认证后仍残留 PAC，`ret` 跳到无效地址。静态 PAC 检查在该映像找到 112 个 double-sign 和 116 个 double-authenticate 模式。

根因是 Makefile 把本机 Linux 构建遗留的 `-mbranch-protection=pac-ret+b-key -fptrauth-calls` 带进 GitHub 的 Apple arm64e 编译。Apple arm64e ABI 已自行生成 B-key 返回地址签名；额外参数造成重复 PAC。旧版成功包用 Apple arm64e 默认 ABI，未额外添加这些通用开关。

## 本地修复（未推送）
- 删除所有通用 PAC 编译开关和 Linux `ld64-wrap` 链接器参数；禁止非 macOS 构建此项目。
- RootHide 路径改用官方 `<roothide.h>` 的 NSString overload，不再用 dlsym 把 C `const char*` 函数当成 NSString 函数调用。
- SpringBoard `%ctor` 不再同步 dlopen/创建 CraneManager；改为主线程首轮循环后安装 Hook，再初始化偏好、枚举 Crane。
- 用命名函数做有界 Hook 重试，移除可能 nil 的弱自引用 block 调度。
- 安装后脚本不再 killall SpringBoard，避免安装时自动注销。
- 新增 `tools/check_pac.py` 和 15 项 `test_safe_mode.py`：定位并拒绝双重 PAC；测试会对真实 clone0.4 CI dylib返回失败。
- 新增独立的 `build-parallelx.yml`：仅安全修复分支触发，产物保留 dSYM / 日志 / JSON 验证；不自动 push 包回 main。
