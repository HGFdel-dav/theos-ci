# 分身账号菜单不显示 / 设置页开关失效 —— 定位与本地修复（2026-11-06）

版本：`0.1.0~alpha391+clone0.6`（上一版 clone0.5）
状态：**仅本地源码修改 + 主机静态检查**。未编译、未出 DEB、未安装、未真机验证。

## 一、用户报告

1. 长按应用调出 ParallelX 菜单，**看不到「分身账号」分组**（没有各行）。
2. 设置页「分身账号」能打开、能列出账号行，但**开关点不动 / 不保存**。

## 二、真机证据（只读取证，未改动设备）

在 alpha391 的 ParallelX 二进制与实机偏好文件上核对：

- `/var/mobile/Library/Preferences/com.moxuan.parallelx.plist` 里菜单模型只有一份：
  `applications / customActions / applicationNames / shortcutSymbols / shortcutImages`。
  **`bottomSwipe*` 这些键是手势动作的取值（back / close …），不是偏好域。**
- 该 plist 中 `applications` 里没有任何 `clonex` / `px.clone` / `px.custom` 条目，
  也就是说旧构建**从来没有写进过菜单**（不是显示层问题）。
- 同样，`com.niubiprass.clonex.plist` 在 jbroot 偏好目录中**不存在** → 开关从未成功写入过。
- 二进制里存在两个入口的重载：
  `-[… performConfiguredAction:fromSearchFavorites:]`（`B28@0:8@16B24`）与
  `-[… performConfiguredAction:]`（`B24@0:8@16`），后者是旧注入器成功 Hook 过的那个。

## 三、三个真因

### 1. 菜单注入写进了不存在的域（死因，证据最强）

旧代码把虚拟条目写进 `bottomSwipeUp/Down/Left/Right` 等自造域，并同时维护
`shortcutSymbols`/`shortcutImages`。ParallelX 的菜单渲染只读 `com.moxuan.parallelx`
里的 `applications` + `customActions`，且只认识它自己的 id 形态
（`px.action.*` / `px.custom.*`）。写别处 = 永远读不到，且使 four-keys 不同步。

**修复**：改为与 ParallelX 自己写自定义动作完全一致的形态 —— 单一域
`com.moxuan.parallelx`，id 用 `px.custom.<FNV-1a 哈希>`（UUID 形态，稳定可复现），
记录带 `type = "clonex.open"` 标记，并写 `applicationNames` / `shortcutSymbols` /
`shortcutImages`（角标图标 = 原版图标右下角 18% 圆底 + 「默」/「分」）。
清理旧条目**按标记 `clonex.open` 判定**，绝不按 `px.custom.` 前缀（前缀是共享的，
按前缀删会误删用户自己建的分组）；另按老前缀 `px.clone.` 清掉本插件早期构建留下的行。

### 2. 引导逻辑把「菜单同步」绑死在 Hook 上（死因，证据强）

旧 `PXBootstrap` 只有在 `PXInstallActionHook()` 返回 YES 后才注册偏好通知、
才执行首次同步；Hook 装不上就重试 25 次后**整个引导放弃** —— 偏好、通知、菜单同步
全都不执行，表现就是「菜单里什么都没有」。

Hook 本身也确实很可能装不上：原版入口在 Swift 类上，ObjC 名可能是
`_TtC9ParallelX12PXPanelEntry` 这类错位名，只按 `NSClassFromString(@"PXPanelEntry")`
查一次、查不到就 `return NO`。

**修复**：
- 首次引导**无条件**加载偏好、注册通知、执行同步；Hook 只做补挂，不再作为前置条件。
- Hook 目标改为**按 ABI 反查**：遍历（一次性缓存的）类列表，用
  `class_getInstanceMethod` 做廉价预筛，再用 `PXCloneClassInstanceMethodMatches`
  校验返回值与参数类型，跳过「继承来的实现」，取真正声明者。
  同时挂 2 参（`…:fromSearchFavorites:`）与 1 参（旧版入口）两个重载。
- `PXResolveClass(@"PXPanelEntry")` 增加**错位名回退**（后缀匹配 + 缓存），
  不再因为类名形态变化就整条链路失效。
- Hook 重试窗口延长到 30 秒（250ms × 120，命名常量），每次收到设置变更通知也会补挂一次。
- 同步加两道 fail-closed 守卫：**偏好存储未加载/出错**、**RunCat 目录为空**时**跳过同步**
  （同步是「不在期望集合里的全删」，用半截数据跑等于替用户删行）。

### 3. 设置页开关接到了一个不存在的方法（死因，证据确凿）

`PXCloneAccountsController.m` 里规格化开关时写的是
`set:@selector(setVisible:forSpecifier:)` / `get:@selector(visibleForSpecifier:)`，
而实现体叫 `- (void)writeShown:(id)value specifier:` / `- (id)readShown:`。
选择器悬空 → 取值恒为 nil（开关恒显示关）、置值无人接收（点了什么都不存）。
对照旧版成功实现（`writeShown:specifier:` / `readShown:`）确认是半途改名没改回来。

**修复**：接线改回 `writeShown:specifier:` / `readShown:`，并加回归测试直接校验
「`set:/get:` 指向的选择器在本文件里必须有实现」。

## 五、未验证 / 残余风险

未做：iOS 编译（需 CI 或你的打包环境）、安装、注销、重启、真机点按验证。
因此以下是**推断，不是已验证结论**：

1. Hook 目标类是否确实被 ABI 反查找对（`performConfiguredAction:fromSearchFavorites:`
   是否就是点击菜单的动作执行点）。菜单行现在与 Hook 解耦，所以即使 Hook 没挂上，
   行也会出现 —— 装后如果「行出现但点了没反应」，就是这一项没对，届时证据很明确。
2. RunCat 目录在真机上的形态是否与 `PXCloneCrane` 的解析一致（`isAvailable` /
   目录刷新是否稳定非空）；若为空，同步会跳过（不删行）但也不会新增行。
3. 设置页写入的沙箱权限：存储走 jbroot 偏好目录的直接文件写入 + flock（与其它插件一致）。
   若 Preferences 进程被沙箱拒绝，页面会显示「存储状态」错误行而不是静默失败。
   —— 本次没有真机证据表明它失败（旧版开关从未被触发过，文件不存在是正常现象）。
4. 与用户自己的 `px.custom.*` 分组共存的边界：仅按 `type` 标记删除，互不影响。
